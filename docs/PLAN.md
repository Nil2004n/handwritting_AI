# Plan (Phase 0 — repository setup, mock slice, review UI)

## Done
- Bare React Native 0.88.1 + TypeScript app (template procedure with
  `--skip-install`; npm 12 `--allow-scripts` restriction workaround documented
  in KNOWN_ISSUES). App name: NotebookOCR (provisional).
- Kotlin Android sources kept as generated by the template (`MainActivity.kt`,
  `MainApplication.kt`); no changes, no fake native modules.
- Domain contracts: `src/domain/document.ts`, `src/domain/ocr.ts`.
- Coordinate convention + contain-mapping helper (`src/utils/coordinates.ts`).
- 5 synthetic PNG fixtures generated by `scripts/generate-fixtures.mjs`
  (Node builtins only, deterministic) + typed fixture documents.
- `MockOcrEngine` implementing the OCR interface (fixture-only, 600 ms
  simulated latency, deep-copy results, structured errors).
- Session store (`src/state/DocumentStore.tsx`): per-document edits, no
  persistence, guarded extraction lifecycle, explicit two-step reset.
- Screens: demo list (with disabled import buttons) + document review
  (image + overlay, block list, raw-vs-edited editors, extract flow).
- Local LaTeX-subset preview (`EquationPreview`, no network/WebView).
- Tests: 38 passing (fixtures, coordinates, engine, editing, parser, UI flow).
- `tsc --noEmit` clean, `eslint` clean.

## Pending / not started
- Real Android debug build (blocked: no Android SDK — see HANDOFF).
- Device/manual testing on a physical phone or emulator.
- Anything from Phase 1.

## Scope boundary
Phase 0 contains NO real OCR. Every recognition-looking result is labeled
demo/mock. No camera, gallery, cloud, auth, database, export, signing, or
store work was started.

## Next phase
Validate the official PaddleOCR Android demo (upstream) to fix the
detector/recognizer integration approach, then design the JS<->Kotlin bridge
per docs/NATIVE_API.md. Do NOT bundle models or write the bridge in Phase 1
until the upstream demo behavior is understood.
